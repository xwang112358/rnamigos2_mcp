# REINVENT (Reinforcement Learning for Molecular Design)

## Algorithm Overview

REINVENT uses reinforcement learning to train a recurrent neural network (RNN) to generate optimized molecules character-by-character as SMILES strings, similar to how language models generate text. Unlike evolutionary algorithms that modify existing molecules, REINVENT generates entirely new molecular structures from scratch. The algorithm consists of two models: a frozen "Prior" RNN pre-trained on general chemistry (ChEMBL dataset) and an "Agent" RNN that starts as a copy of the Prior but gets fine-tuned through policy gradient reinforcement learning. The Agent generates molecules, receives reward signals from the oracle scoring function, and learns to increase the probability of generating high-scoring structures. While REINVENT can generate molecules de novo, the reference SMILES file plays an important role by seeding the experience replay buffer - high-scoring molecules from the file can be included in training batches to provide examples of successful structures and stabilize learning. The algorithm balances exploration (generating diverse novel molecules) with exploitation (focusing on known high-scorers) through augmented likelihood, which combines the Prior's chemistry knowledge with oracle scores weighted by sigma.

## Hyperparameters

**`learning_rate`** (default: `0.0005`)
- Learning rate for the Adam optimizer that trains the Agent RNN model
- Controls how quickly the Agent adapts its parameters to maximize oracle scores
- Too high (>0.001): Training becomes unstable, Agent may collapse to generating invalid or repetitive molecules
- Too low (<0.0001): Very slow convergence, may not reach high-scoring solutions within the oracle budget
- Default 0.0005 is empirically validated for stable convergence across diverse molecular tasks
- The Agent is continuously updated at every training step, so this affects the entire optimization trajectory

**`batch_size`** (default: `64`)
- Number of molecules generated by the Agent and evaluated by the oracle per training step
- Larger batches (128+) provide more stable gradient estimates and smoother training but slower iteration
- Smaller batches (32-) enable faster iteration and more responsive adaptation but noisier gradients
- Trade-offs:
  - Batch 32: Faster per-step, good for quick experiments, higher training variance
  - Batch 64: Standard balanced choice for speed and stability
  - Batch 128+: Very stable gradients, good for final production runs, slower feedback
- Each batch directly translates to oracle calls, so this controls the rate of oracle consumption

**`sigma`** (default: `500`)
- Weight multiplier for the oracle score in the augmented likelihood function
- Formula: `Augmented_likelihood = log P(molecule|Prior) + sigma × Oracle_score`
- This is the most critical hyperparameter for controlling REINVENT's behavior
- Effects on search strategy:
  - sigma = 0: Agent stays identical to Prior (no optimization occurs)
  - sigma = 100-300: Conservative search, Agent stays close to chemically valid Prior distribution
  - sigma = 500-750: Balanced approach, standard for most tasks, good exploration-exploitation trade-off
  - sigma = 1000+: Aggressive optimization, maximizes score but risks generating chemically invalid or unstable molecules
- Higher sigma: Agent focuses more on oracle score, less on chemical validity from Prior
- Lower sigma: Agent prioritizes chemistry validity, explores more cautiously
- Tune this parameter if: molecules are invalid (decrease sigma) or optimization plateaus too early (increase sigma)

**`experience_replay`** (default: `24`)
- Number of previously discovered high-scoring molecules resampled and included in each training batch
- Prevents catastrophic forgetting: ensures Agent remembers successful solutions found earlier in training
- Mechanism:
  1. Agent generates `batch_size` new molecules
  2. System samples `experience_replay` molecules from the memory buffer (stores all high-scorers)
  3. Agent trains on the combined set of (new + replayed) molecules
- Benefits:
  - Stabilizes training by mixing exploratory new samples with proven successful examples
  - Improves sample efficiency by reusing high-scoring molecules for multiple training steps
  - Prevents mode collapse where Agent forgets how to generate diverse solutions
- Value effects:
  - 0: Pure on-policy RL, no replay, can suffer from catastrophic forgetting
  - 8-16: Light replay, more exploration-focused, faster adaptation to new regions
  - 24-32: Standard balanced replay, good stability and exploration
  - 50+: Heavy replay, very conservative, slower exploration but stable training
- The memory buffer stores the best molecules encountered so far across all training steps
